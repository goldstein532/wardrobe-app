# Витрина nasonchikh wardrobe — план

Telegram Mini App + бот, витрина наличия, синхронизируется с каналами по хэштегам.

## Источники

| Канал | Что там | Как обрабатываем |
|---|---|---|
| nasonchikh wardrobe | основные товарные посты | `#наличие`, `#едет`, `#продано` |
| nasonchikh express | вещи в пути | обычно `#едет`; бот тоже админ этого канала |
| Группа обсуждения wardrobe | «Доп фото 👇» в комментариях | фото **только от админов/канала** добавляются в галерею товара отдельным блоком «Детали» |

Посты без статусного хэштега («NEW DROP TODAY» и т. п.) игнорируются.

### Дубли между каналами
- Пост из express, пересланный в wardrobe: бот видит `forward_origin` (канал + message_id) и связывает его с уже существующим товаром, а не создаёт новый.
- Вещь приехала, и админ сделал **новый** пост с `#наличие`: если совпадают бренд, название и размер с товаром «в пути», бот пишет админу в личку «Это та же вещь, что N° 0031?» [Да, объединить] [Нет, новая]. При «Да» товар меняет статус и получает новые фото, номер N° сохраняется.
- Кнопка «Открыть пост» ведёт на самый свежий пост товара (приоритет у wardrobe).

## Правило «одна вещь — один товар»
Рекомендация для админа: одна вещь в одном посте. Если пост всё-таки с несколькими вещами (несколько размеров, «for each»):
1. Если число фото равно числу размеров (как с джинсами: 2 фото, 31 / 32), бот делит пост на отдельные товары по порядку: фото 1 → размер 1 и т. д.
2. Иначе бот создаёт по товару на размер с общими фото.
3. В обоих случаях бот пишет админу в личку, как он разделил пост: [Верно] [Исправить] [Скрыть пост].

## Формат поста (что парсим)
```
<Бренд> <Название> [Сезон SS14/AW01]  <эмодзи-логотип>
> описание (цитата)
•Size: 40 (40-41)        | Size - 31 / 32
•Cond: 10/10 (NEW, ...)  | Cond - 9/10
•Price: 30.900₽          | Price - 13.900 (for each)
#наличие | #едет | #продано  (+ «SOLD» в тексте)
```
Бренд определяется по словарю брендов (дополняется). Поле, которое не разобралось, просто не показывается. Кнопка «Купить / вопрос» ведёт к @nasonchikh_mngr.

## Смена статуса
- Основной способ: редактирование поста (`edited_channel_post`).
- Запасной: админ пересылает пост боту → кнопки [В наличии] [В пути] [Продано] [Скрыть]. Защита контента в канале выключена, так что пересылка работает.
- Дублирующий: `/status <N°> <статус>`, `/remove <N°>`.
- Удалённые посты: ночная проверка через `editMessageReplyMarkup` («not found» → товар скрывается).

## Хостинг (бесплатный, GitHub)
- Витрина: GitHub Pages (HTTPS, работает в РФ).
- Синхронизация: GitHub Actions по расписанию раз в 5 минут. Задача делает `getUpdates` → парсит → готовит фото → коммитит `catalog.json` и фото → Pages публикуется.
- Фото: бот берёт самый большой вариант из поста (до 1280 px, HD до 2560 px). Для сетки WebP 720 px, для карточки оригинальный размер в WebP высокого качества (q≈88), без уменьшения.
- Задержка 5–15 минут, бот отвечает с той же задержкой.
- Избранное хранится в Telegram CloudStorage. Подписки и пользователи — в зашифрованном файле в репозитории (секрет в GitHub Secrets).
- Ядро (парсер, модели, логика статусов) не зависит от хостинга: тот же код позже запускается на VPS через вебхук без переделок.

## Дизайн — выбрана концепция 01 «Бирка»
Макет: `design/concepts.html`.
- Белый фон, чёрный текст, серые только служебные (#f2f2f2 подложка фото, #8a8a8a подписи, #e6e6e6 линии). Акцентного цвета нет.
- Шрифты: Inter Tight (основной) + IBM Plex Mono (номера, размеры, статусы, подписи полей), с кириллицей.
- Сетка в 2 колонки, фото 3:4. Под фото «бирка»: N° 001, размер, бренд, название, цена. Четыре стежка по углам бирки.
- «В пути» — типографская пометка «— В ПУТИ», без цветной плашки.
- Карточка: свайп-галерея, таблица полей (размер, состояние, подлинность, получение), описание, MainButton «Купить / задать вопрос» чёрного цвета.
- Тёмная тема: та же композиция в инверсии (фон #0b0b0b, текст #f2f2f2).

## Этапы
- a. Парсер + модели + логика статусов + тесты на реальных постах
- b. Сборщик каталога (`catalog.json`, фото) + GitHub Actions
- c. Импорт истории каналов (Telethon, одноразово, локально)

- f. Уведомления и подписки
- g. Оформление бота, инструкция @BotFather и GitHub
